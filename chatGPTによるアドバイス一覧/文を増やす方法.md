```markdown
# 文を「安全に増やす」ための簡易ルール

## 前提
- **増やす＝情報を盛ることではない**
- **出来事を分解して提示すること**
- **増やしているのは「情報」ではなく「認知にかかる時間」**

---

## 基本構造（必要なところまで分解）

```

① 状態（余裕・緊張・未認識）
② 発話／意図
③ 起点動作（トリガー）
④ 現象（見えたもの・起きたこと）
⑤ 結果（方向・影響）

```

※ ①〜⑤は **全部書く必要はない**  
※ 読者が映像を作れるところで止める  
※ **結論（⑤）は最後に置くと余白が生まれやすい**

---

## 書くときの絶対条件
- **全部「Aが知覚できる情報」に限る**
- 数値・専門用語・後講釈は書かない
- A基準で表現する（大きさ・速さ・位置）
- **Aがまだ理解できていないことは「分からないまま」書く**

---

## 認知の余白とは何か（重要）

- 余白＝何も起きていない時間 **ではない**
- 余白＝**読者が理解・判断・想像するための処理時間**

### 余白は次の形で作る
- 理解が遅れる
- 判断を保留する
- 確認してしまう
- 違和感だけ提示する

---

## 認知の余白を作る典型パターン

```

すぐには理解できなかった。

```
```

何が起きたのか、分からない。

```
```

もう一度、見た。

```
```

そういうものだと、思っていた。

```

※ 情報は増えていない  
※ **理解までの過程を可視化しているだけ**

---

## 増やすか迷ったときの判断
- 起点（何が原因？）
- 現象（何が起きた？）
- 結果（どうなった？）
- **認知（すぐ分かった？）**

→ 1つでも曖昧なら **そこを1文足す**

---

## 良い増やし方（例）

```

手をかざす。
火が生まれる。
飛んでいく。

```
```

見慣れない天井だった。
村の家とは、どこか違う。

```

---

## 悪い増やし方（例）

```

高温の魔力による火球が生成された。

```
```

高度な魔法理論に基づく現象だった。

```

※ 認知の余白がなく、処理を読者に強制している

---

## 視点安全チェック
> これは「今この瞬間のA」が  
> 見る／聞く／感じることができるか？

- Yes → 書いてOK
- No → 書かない／匂わせる

---

## 分解すべき瞬間の見極め（重要）

次のどれかに当てはまる瞬間だけ分解する：

- 状況が変わる（安全→危険）
- 認知がズレる（見たが分からない）
- 感情が切り替わる（安心→焦り）

※ **全部分解しない**
※ 分解は「効かせたい瞬間」だけ

---

## 応用指針
- 緊急・一瞬の場面 → 分解を減らす
- 格付け・余裕を見せたい → ①を足す
- 魔法・攻撃 → ③〜⑤を優先
- 覚醒・発見・理解 → **認知の遅れを足す**

---

## 最終チェック（読み心地）
- 情報は理解できるか？
- 読者は立ち止まれるか？
- 処理が同時要求になっていないか？

---

## 合言葉
> **「盛らずに、分ける」**  
> **「人は一瞬で分からない」**
```

---

### 補足（使い方のコツ）

* 書いている最中は **①〜⑤を意識しない**
* 書いたあとに

  > 「ここ、分解できるか？」
  > とチェックする
* **増やすフェーズと削るフェーズは分ける**

むしろ **チェックリスト化すると、このルールは一気に使いやすくなります。**

以下は、あなたが書いた内容＋追加したアドバイスを
**「執筆後に上から順に確認できるチェックリスト」** に再構成したものです。
そのままコピペして使えます。

---

```markdown
# 文を「安全に増やす」ためのチェックリスト

---

## 0. 前提確認（最初に見る）

- [ ] 文を増やそうとして「新情報」を足していない  
- [ ] 出来事そのものは変えていない  
- [ ] 増やしているのは「理解にかかる時間」だけである  

---

## 1. 分解ポイント確認（①〜⑤）

以下の要素が **必要なところだけ** 書かれているか？

- [ ] ① 状態（余裕・緊張・未認識など）
- [ ] ② 発話／意図（言おうとした・考えた）
- [ ] ③ 起点動作（視線・振り向く・手を伸ばすなど）
- [ ] ④ 現象（見えたもの・起きたこと）
- [ ] ⑤ 結果（方向・影響・確定）

※ 全部にチェックが入る必要はない  
※ 読者が映像を作れたらOK

---

## 2. 認知の余白チェック（重要）

- [ ] 出来事を「一瞬で理解していない」文が入っている  
- [ ] 判断や結論を **最後まで引っ張れている**  
- [ ] 「分からない」「違う気がする」「確認する」など  
      認知の遅れが1文以上ある  

例：
- 「すぐには理解できなかった」
- 「何が起きたのか分からない」
- 「もう一度、見た」

---

## 3. 視点安全チェック（必須）

- [ ] この文は「今この瞬間のA」が  
      見る／聞く／感じることができるか？
- [ ] 後講釈・神視点・数値説明になっていないか？
- [ ] Aが理解していないことを、断定して書いていないか？

---

## 4. 増やしすぎ防止チェック

- [ ] すべての動作を分解していない  
- [ ] 緊急・高速な場面では分解を減らしている  
- [ ] 「読者が考える余地」が「待たされる時間」になっていない  

判断基準：
- [ ] この1文で、読者の頭は動いているか？

---

## 5. 迷ったときの判断基準

次のうち **1つでも曖昧なら、1文足す**：

- [ ] 起点：何が原因で起きた？
- [ ] 現象：何が起きた？
- [ ] 結果：どうなった？
- [ ] 認知：Aはすぐ理解できた？

---

## 6. 良い増やし方になっているか

- [ ] 動作・知覚で増やしている  
- [ ] 説明文で増やしていない  

### OK例
```

手をかざす。
火が生まれる。
飛んでいく。

```

### NG例
```

高温の魔力による火球が生成された。

```

---

## 7. 最終読み心地チェック

- [ ] 情報は理解できる  
- [ ] 読者は立ち止まれる  
- [ ] 同時に考えさせすぎていない  

---

## 合言葉（最後に確認）

- **盛らずに、分ける**
- **人は一瞬で分からない**
```

---

### 使い方のおすすめ

* ✍ 書いた直後に **上から一度チェック**
* ✂ 削るときは「3. 視点」「4. 増やしすぎ」だけ見る
* 🔁 増やすフェーズと削るフェーズは分ける
